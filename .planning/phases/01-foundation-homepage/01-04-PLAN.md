## Shared motion contract

`MotionPreferencesProvider` and `useMotionPreferences()` expose hydrated readiness, OS reduced preference, local paused preference, `motionAllowed`, and `setPaused`. Server and first client render remain static and identical. Reduced motion takes precedence over every local resume choice. Store only the pause preference; handle blocked/malformed storage without throwing. MotionConfig uses `reducedMotion="user"` with imports from `motion/react`, but custom CSS/canvas loops also consume the explicit shared policy.

Only the portrait and constellation are persistent hero motion. The visible pause button is keyboard usable and states Pause animations / Resume animations; reduced mode explains that system preference keeps motion off. No WebGL, physics, GSAP or particle dependency. Existing npm scripts are used; Task 1 creates the complete test suite, with targeted groups run as each slice is implemented. Full-suite failures cannot be treated as skipped acceptance.
