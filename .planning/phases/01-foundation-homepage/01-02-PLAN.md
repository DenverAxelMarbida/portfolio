## Interfaces and ownership

- Build-only `ProjectSchema`, `PublicProject`, `PublicManifest` and inferred types live in `scripts/content/schema.ts`; runtime UI imports these only with `import type`. Zod and raw author records must not enter the browser import graph.
- `validateContent({contentRoot})` validates all source records, profile configuration and references. `generatePublicContent({contentRoot, outputRoot})` recreates `.generated/public-content.json` and `.generated/media/` from an explicit allowlist. The production CLI fixes these roots to repository-local paths; test overrides are confined to owned temporary fixture directories.
- Manifest contract: schema version, public profile and a deterministically ordered `projects` array. Profile accepts supplied name/title/headline, nullable introduction, GitHub/email and nullable original-image reference. Until `content/profile.json` is authored in 01-03, use only the supplied identity, never invented introductory prose.
- Pure `getPublishedProjects(manifest, {featuredOnly})` and `getProjectBySlug(manifest, slug)` operate on already-filtered public data. Neither can read source files or resurrect drafts.
- Task 1 creates `content:check` and `content:generate`; `dev` and `build` run generation before any Vite import. Source changes in dev require restarting through `npm run dev`, which regenerates before serving; document this explicitly and never serve raw authoring files. Automatic source watching is not required. `test` was declared in 01-01; this plan supplies its first tests.
- Fixture build tests use an owned temporary workspace with copied build/source/config files and approved dependency resolution. Preserve relative imports and invoke the same real build entry there. Never swap the repository's real authoring records or share generated output between concurrent tests. All temporary roots are removed in test cleanup; application artifacts remain untouched by fixture builds.
